# The front end

`app/` is two things that should not be confused: an **Electron shell** that owns a window and a child
process, and a **React renderer** that draws the answers an HTTP API gives it.

The shell holds no business logic. That is the whole point, it is replaceable in a weekend, and the
renderer would work unchanged against a hosted Avocado.

---

## Running it

```bash
dotnet build src/Avocado.Server     # the shell resolves the backend from bin/Debug
cd app
npm install
npm run electron:dev                # vite build, then electron .
npm run typecheck
```

The vault defaults to `~/Documents/Avocado`; point elsewhere with `AVOCADO_VAULT`.

> **`Cannot read properties of undefined (reading 'whenReady')`** means `ELECTRON_RUN_AS_NODE=1` is
> set in your environment. VS Code sets it for the processes it spawns, so every terminal inside the
> editor inherits it, and it makes Electron run as plain Node, where `require('electron')` returns
> *the path to the binary* rather than the API. Unset it, or launch from a terminal outside the editor.

## The shell

```
app/electron/
  main.ts       window, CSP, the IPC channels, lifecycle
  backend.ts    spawns Avocado.Server, reads the AVOCADO_READY handshake off stdout
  preload.ts    the entire surface the renderer gets
  drives.ts     removable volumes, for the recovery key
```

`main.ts` decides two paths and passes both to the backend:

```ts
const vaultDirectory = process.env.AVOCADO_VAULT ?? path.join(app.getPath('documents'), 'Avocado')

const localState =
  process.platform === 'win32' && process.env.LOCALAPPDATA
    ? path.join(process.env.LOCALAPPDATA, 'Avocado')
    : app.getPath('userData')

const workingDirectory = path.join(localState, 'working')
```

`userData` is deliberately **not** used on Windows: Electron points it at Roaming, which a domain
profile copies between machines, and working copies are plaintext that must stay on one machine. On
macOS and Linux `userData` already is local.

### The preload surface

Seven named channels, and that is the complete list:

| Channel | What it does |
|---|---|
| `connection` | The backend's URL and this launch's token |
| `chooseFolder` | The native folder picker, for the setup wizard |
| `removableDrives` | Removable volumes only, never this computer's own disk |
| `saveRecoveryKey` | Writes the recovery key to a chosen removable drive |
| `exportRecoverySheet` | Renders the current page to a PDF |
| `openWorkingCopy` | Hands a path to the OS default application |
| `saveAs` | Writes generated bytes where the user asks |

With `contextIsolation` and `sandbox` on, a bug in the UI, or in anything it renders, cannot reach
the filesystem, spawn a process or read the vault. Anything that genuinely needs the OS gets its own
channel, reviewed on its own merits, rather than a general-purpose bridge.

`openWorkingCopy` refuses any path outside the working directory. The renderer never chooses that
path: the backend decrypts the document and answers with where it put it.

### Styling

Tailwind CSS v4 via `@tailwindcss/vite`, over the design system's `tokens.css` verbatim.

`theme.css` maps Tailwind's palette **at the variables**, not at their values:

```css
@theme {
  --color-panel: var(--surface-panel);
  --color-brand: var(--brand);
}
```

so `bg-panel` follows the theme switch and there is never a second source of truth to drift from
`tokens.css`.

> **What is deliberately not in `@theme`: the type scale and the radius scale.** `tokens.css` already
> owns `--text-*` and `--radius-*`, it is imported unlayered, and an unlayered declaration beats a
> layered one whatever the specificity. Redeclaring `--text-display: 28px` in `@theme` looked right and
> did nothing: tokens.css kept its own value, a `font` shorthand, `600 28px/34px …`, which is not a
> valid `font-size`, so every `.text-display` silently collapsed to the inherited 13px. The nine type
> steps are the `.type-*` classes in `theme.css`, applying the shorthand `tokens.css` defines.

Radius comes from `tokens.css` unchanged: `2` badge · `4` input, button, row · `6` card, menu ·
`8` panel · `10` dialog and ⌘K · `999` avatar.

**Pills and badges derive their height from padding plus an explicit line box**, never from a fixed
height. A pinned height with an inherited 20px line-height leaves the line box taller than the content
box the moment a border appears, which puts the digits a pixel off centre in the bordered variant and
correctly in the plain one.

### Design system fidelity

The design handoffs are held outside this repository, one folder per screen, each with its own specification
and a `.dc.html` reference. Every colour, size, row height and padding in them is final. When
implementation and handoff disagree, the handoff wins unless there is a stated reason; the reasons
that exist are in the commit messages and in comments beside the code.

### API access

`src/api.ts` is the only place `fetch` is called.

```ts
api<T>(path, init)             // bearer token, ProblemDetails → French message
post<T>(path, body)
upload<T>(path, formData)      // no JSON content type, or multipart breaks
download(path, fileName)       // blob, because a plain href has no Authorization header
saveAs(path, fileName)         // through the shell's save dialog
```

The content type is set **only for string bodies**. Forcing `application/json` on a `FormData` body
strips the multipart boundary and produces a `415`.

Every write surfaces its failure. A rejected promise nobody catches shows up as
`Uncaught (in promise) ApiError` in a console the user never opens, and as nothing at all on screen,
which is indistinguishable from the action having worked.

### State

There is no state library. Each screen fetches what it draws and reloads on change; `AppShell` owns
the selection and the creation dialogs, so `⌘N`, the accueil and the list all open the same one.

> **Read a value you do not want as a dependency through a ref, not through the closure.** The dossier
> list's `reload` left `selected` out of its dependency array, correctly, or it would refetch on every
> click, and then read it from the closure, which captures the value from the render that created the
> callback: `null`, on mount. Every later reload took the "nothing is selected" branch and jumped to
> the first row, which is a favourite. Recording an invoice moved her somewhere else.

## Printing

The A4 recovery sheet is the one surface not styled with utilities: it is measured in millimetres and
must stay legible from a nearly empty cartridge, so it has its own `print.css`.

It is **portalled to `document.body`**, and the print stylesheet hides `#root`. Rendering it inside the
wizard meant the print rules hid the sheet along with everything else, which is exactly why printing
once produced a blank page.
